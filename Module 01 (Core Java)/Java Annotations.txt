
# Java Annotations

## 1. Introduction

Suppose we have a method in a parent class.

```java
class Animal {

    public void sound() {

        System.out.println("Animal Sound");
    }
}
```

Now we want to override it.

```java
class Dog extends Animal {

    public void sound() {

        System.out.println("Bark");
    }
}
```

Everything works.

But suppose we accidentally write

```java
class Dog extends Animal {

    public void sounds() {

        System.out.println("Bark");
    }
}
```

Notice

```text
sound()
```

became

```text
sounds()
```

The compiler doesn't report an error.

Instead,

Dog now has a completely new method.

To prevent such mistakes, Java introduced **Annotations**.

---

# 2. What is an Annotation?

> An Annotation is metadata (information about the program) that provides instructions to the compiler, JVM or other tools.

Annotations do **not** directly change the program logic.

They provide additional information.

Introduced in

* Java 5

---

# 3. Syntax

Annotations start with

```text
@
```

Example

```java
@Override
```

or

```java
@Deprecated
```

# 4. Built-in Annotations

Java provides several built-in annotations.

Some common ones are

* @Override
* @Deprecated
* @SuppressWarnings
* @FunctionalInterface
* @SafeVarargs

---

# 5. @Override

Most commonly used annotation.

Example

```java
class Animal {

    public void sound() {

        System.out.println("Animal");
    }
}

class Dog extends Animal {

    @Override
    public void sound() {

        System.out.println("Bark");
    }
}
```

Compiler verifies

* method exists in parent
* correct signature

---

## Incorrect Override

```java
class Dog extends Animal {

    @Override
    public void sounds() {

        System.out.println("Bark");
    }
}
```

Compilation Error

Because

```text
sounds()
```

doesn't override any parent method.

---

# 6. @Deprecated

Indicates

> This method/class should no longer be used.

Example

```java
class Calculator {

    @Deprecated
    public void add() {

        System.out.println("Old Method");
    }
}
```

Usage

```java
Calculator c = new Calculator();

c.add();
```

Compiler gives a warning.

Program still runs.

---

# 7. @SuppressWarnings

Suppresses compiler warnings.

Example

```java
@SuppressWarnings("unchecked")
```

Example

```java
import java.util.ArrayList;

public class Main {

    @SuppressWarnings("rawtypes")
    public static void main(String[] args) {

        ArrayList list = new ArrayList();

        list.add("Java");
    }
}
```

Without annotation

Compiler shows warning.

With annotation

Warning disappears.

---

# 8. @FunctionalInterface

Applied on interfaces.

Ensures

exactly one abstract method exists.

Example

```java
@FunctionalInterface
interface Printable {

    void print();
}
```

Valid.

---

Invalid

```java
@FunctionalInterface
interface Printable {

    void print();

    void display();
}
```

Compilation Error.

---

# 9. @SafeVarargs

Used with methods having generic varargs.

Example

```java
@SafeVarargs
public final <T> void display(T... values) {

}
```

Suppresses unsafe generic varargs warning.

Mostly used in library code.

# 26. Complete Example

```java
@interface StudentInfo {

    int id();

    String name();

    String course() default "Java";
}

@StudentInfo(

        id=101,

        name="Harsh")

class Student {

}

public class Main {

    public static void main(String[] args) {

        System.out.println("Program Executed");
    }
}
```

Output

```text

```

Notice

The annotation itself does nothing because no code is reading it.

# 27. How Do Frameworks Use Annotations?

Suppose we write

```java
@RestController
class StudentController {

}
```

Spring Boot scans your class using **Reflection**.

It detects

```text
@RestController
```

and automatically registers the class as a REST controller.

Similarly,

```java
@Entity
```

tells Hibernate to map a class to a database table.

The annotation is **just metadata**; the framework decides what to do with it.

## Types of Annotations

Java annotations can be classified into three main types.

---

# 1. Marker Annotation

A marker annotation does **not** contain any elements (members).

It is simply used to mark or identify a program element.

Example

```java
@interface Test {
}
```

Usage

```java
@Test
class Student {

}
```

Some built-in marker annotations

* `@Override`
* `@Deprecated`

---

# 2. Single Value Annotation

A single value annotation contains only one element, usually named `value`.

Example

```java
@interface Version {

    int value();
}
```

Usage

```java
@Version(2)
class Student {

}
```

The above is equivalent to

```java
@Version(value = 2)
class Student {

}
```

If the only element is named `value`, Java allows us to omit `value=`.

---

# 3. Multi Value Annotation

A multi value annotation contains two or more elements.

Example

```java
@interface StudentInfo {

    int id();

    String name();

    String[] skills();
}
```

Usage

```java
@StudentInfo(
        id = 101,
        name = "Harsh",
        skills = {"Java", "Spring Boot", "SQL"}
)
class Student {

}
```

---

# Summary

| Annotation Type         | Elements              | Example                                               |
| ----------------------- | --------------------- | ----------------------------------------------------- |
| Marker Annotation       | No elements           | `@Override`, `@Deprecated`                            |
| Single Value Annotation | One element (`value`) | `@Version(2)`                                         |
| Multi Value Annotation  | Two or more elements  | `@StudentInfo(id=101, name="Harsh", skills={"Java"})` |

### Teaching Tip

Tell students to remember the three types like this:

* **Marker** → Just marks something (`@Override`)
* **Single Value** → One piece of information (`@Version(2)`)
* **Multi Value** → Multiple pieces of information (`@StudentInfo(...)`)

---

# Allowed Types for Annotation Elements

Annotation elements can have **only the following data types**.

| Data Type                                          | Allowed? | Example              |
| -------------------------------------------------- | :------: | -------------------- |
| Primitive Types (`int`, `double`, `boolean`, etc.) |   ✅ Yes  | `int id();`          |
| `String`                                           |   ✅ Yes  | `String name();`     |
| `Class`                                            |   ✅ Yes  | `Class<?> type();`   |
| `enum`                                             |   ✅ Yes  | `Day day();`         |
| Annotation                                         |   ✅ Yes  | `Author author();`   |
| Array of Allowed Types                             |   ✅ Yes  | `String[] skills();` |

## Memory Trick

Annotation elements can contain only:

* ✅ Primitive types
* ✅ `String`
* ✅ `Class`
* ✅ `enum`
* ✅ Another annotation
* ✅ Arrays of the above
---

A good classroom example is an annotation that stores **metadata about a student project**.

### Step 1: Create the Annotation

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.time.LocalDate;

@Retention(RetentionPolicy.RUNTIME)
@interface ProjectInfo {

    String name();

    String value();

    String[] technologies();

    String startDate();
}
```

> **Note:** Although you asked for a `LocalDate` field, **annotation elements cannot be of type `LocalDate`**. The allowed types are:
>
> * Primitive types
> * `String`
> * `Class`
> * `enum`
> * Annotation
> * Arrays of the above
>
> Therefore, dates are typically stored as `String` or an `enum`.

---

### Step 2: Apply the Annotation

```java
@ProjectInfo(
        name = "Student Management System",
        value = "Final Year Project",
        technologies = {"Java", "Spring Boot", "MySQL"},
        startDate = "2026-07-25"
)
class StudentProject {

}
```

---

### Step 3: Read the Annotation Using Reflection

```java
public class Main {

    public static void main(String[] args) {

        Class<StudentProject> cls = StudentProject.class;

        ProjectInfo info = cls.getAnnotation(ProjectInfo.class);

        System.out.println("Name         : " + info.name());
        System.out.println("Value        : " + info.value());
        System.out.println("Start Date   : " + info.startDate());

        System.out.println("Technologies :");

        for (String tech : info.technologies()) {
            System.out.println(tech);
        }
    }
}
```

---

### Output

```text
Name         : Student Management System
Value        : Final Year Project
Start Date   : 2026-07-25
Technologies :
Java
Spring Boot
MySQL
```

---

## Interview Question

**Q:** Why didn't we use `LocalDate` in the annotation?

**A:** Because annotation elements can only be of specific types:

* Primitive types
* `String`
* `Class`
* `enum`
* Another annotation
* Arrays of the above

`LocalDate` is a regular class, so it **cannot** be used as an annotation element. In practice, dates are stored as `String` or represented using an `enum`.
