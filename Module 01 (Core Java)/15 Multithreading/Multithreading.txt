Multithreading
==============
Multitasking
------------
- Execution of multiple tasks (processes, or threads) at the same time.

There are 2 types of Multi Tasking:
1. Multi-processing
2. Multi-threading

Multiprocessing
------------
- Execution of multiple processes (softwares, applications) on an OS at the same time.

Ex: Eclipse and Teams working on the same system

Multithreading
--------------
- Execution of sub processes (aka threads) withing 1 application 

Ex: In Teams
	- Screen is shared
	- recording is happening
	- video is working
	- sound is transferring

Threads
-------	
- The lightweight sub processes within a process are known as Threads
- A thread is the smallest unit of processing
- The multiple threads working together is known as Multi-threading
- It could be thought of as a separate path of execution.
- Without multi-threading, there will be a sequential flow

Why create Threads?
-------------------

We create threads to make a program do multiple things at the same time — instead of waiting for one task to finish before starting the next.

---

⚙️ 1. To achieve concurrency (parallel execution)

=> Normally, programs run sequentially — one line at a time.
=> Threads let you run multiple parts of your program concurrently.

Example:

Imagine a text editor (like MS Word):

=> One thread keeps checking for spelling mistakes.
=> Another thread saves the file automatically.
=> Another thread lets you keep typing.
  All of these happen simultaneously using threads.

---

⚡ 2. To improve performance

If your program has tasks that can run independently (like reading a file, downloading data, updating the screen), threads help utilize CPU and waiting time better.

Example:

While one thread waits for a file to download, another thread can process previously downloaded data.

---

🖥️ 3. To keep applications responsive

=> In GUI or web applications, the main thread handles the user interface.
=> If you perform a long operation (like network call) on it, the UI will “freeze.”
=> By moving heavy work to a background thread, your UI stays smooth.

Example:

When a React app fetches data, it doesn’t block rendering — that’s similar to how threads help in backend Java programs.

---

🔄 4. To handle multiple users or tasks simultaneously

=> In servers, threads help handle multiple clients at once.
=> Each user request can be handled by a separate thread, so the server doesn’t make one user wait for another.

Example:

=> Web server → multiple users requesting pages.
=> Chat app → each user’s message handling in a separate thread.

---

💡 Summary

| Reason         | Benefit                     |
| -------------- | --------------------------- |
| Concurrency    | Run tasks at the same time  |
| Performance    | Utilize CPU efficiently     |
| Responsiveness | Keep UI smooth              |
| Scalability    | Handle multiple users/tasks |

Ways to create a thread
=======================
There are 2 ways of creating a thread:

1. Extending the Thread class
2. Implementing the Runnable interface

Extending the thread class
--------------------------
- Thread class implements Runnable interface
- It is present in java.lang package
- It contains many constructors and methods for thread manipulation	

Implementing the Runnable interface
-----------------------------------
- Create an object of class implementing the runnable interface
- Wrap it in a Thread constructor
- Calling the start() on thread object	
- Runnable is the parent interface in Multithreading
- It is a functional interface
- Present in java.lang package
- Containing the abstract method: void run()
	
- run() is the place where we have to write the logic of our sub-processes
For ex: spell checking logic, grammar check logic, video recording logic etc

- run() is the starting point of the functionality of any sub process (similar to main())

Runnable v/s Thread
===================

1. Inheritance:

   => `Runnable`: Allows your class to extend another class (Java allows only single inheritance).
   => `Thread`: If you extend `Thread`, you cannot extend any other class.


2. Code Reusability:

   => `Runnable`: You can reuse the `Runnable` instance with multiple `Thread` objects.
   => `Thread`: Cannot reuse the thread object once it has completed.

3. Best Practice:

   => `Runnable`: Preferred for most applications, especially when using thread pools or executors.
   => `Thread`: Used rarely — mainly if you need to override additional methods in the `Thread` class.

5. Flexibility:

   => `Runnable`: More flexible and scalable — ideal for large-scale applications.
   => `Thread`: Less flexible — tightly couples the thread behavior with task logic.

6. Lightweight:

   => `Runnable`: Lightweight — only contains the logic.
   => `Thread`: Inherits the full thread implementation.

---

✅ When to Use What?

=> Use `Runnable` when your class needs to extend another class.
=> Use `Thread` when your class is a standalone one.

Life cycle of a thread
======================
- The life cycle of a thread from its creation to destruction is known as Thread Lifecycle. 
- It is important to note that the life cycle of the thread in java is controlled by JVM.
- According to Oracle, thread lifecycle has only 4 states: New, Runnable, Non-runnable & Terminated
- But for better understanding the threads, lets understand it in the following 5 states:
- New, Runnable, Running, Non-Runnable (Blocked) and Terminated state

Refer image - 02_thread_life_cycle.jpg
1. New
The thread is in new state when we create an instance of Thread class before start() method is invoked.

2. Runnable
The thread is in runnable state after invocation of start () method, but the thread scheduler has not selected it to be the running thread. 

3. Running
The thread is in running state if the thread scheduler has selected it. 

4. Non-Runnable (Blocked)
This is the state when the thread is still alive, but is currently not eligible to run. 

5. Terminated
A thread is in terminated or dead state when its run() method exits. 

Thread Safety vs Unsafety
=========================
Race Condition
--------------
When 2 threads want to access a shared resource at the same time, it is known as Race Condition.

Thread Unsafety
---------------
It is a good feature if the code block is non-critical.
But if its the other way around, race condition may produce inconsistent results (aka Thread Unsafe code)

To stop this thread interferences, we need thread safety

Synchronization
===============
- Synchronization is the capability to control the access of multiple threads to any shared resource.
- Synchronization is better option where we want to allow only one thread to access the shared resource.

Why use Synchronization?
------------------------
The synchronization is mainly used to
- To prevent thread interference.
- To prevent consistency problem.
- If the data worked upon by the threads keep on updating, we should go for synchronization

Types of Synchronization
------------------------
There are two types of synchronization:

1. Process Synchronization
2. Thread Synchronization

Here, we will discuss only thread synchronization. 

Thread Synchronization
----------------------
There are two types of thread synchronization:
1. Mutual Exclusion
2. Cooperation (Inter-thread communication in java)

Lock
====
- Synchronization is built around an internal entity known as the lock or monitor. 
- Every object has a lock associated with it. 
- A thread that needs consistent access to an object's fields has to acquire the object's lock.
- The thread releases the lock when it's done with it. 	

Mutual Exclusion
----------------
Mutual Exclusion helps keep threads from interfering with one another while sharing data. 

This can be done by 2 ways:

1. By synchronized method
2. By synchronized block

- Synchronization can be achieved by using the keyword `synchronized`.
- It can be used on methods and blocks.

Java Synchronized Method
------------------------
- If we declare any method as synchronized, it is known as synchronized method.
- Synchronized method is used to lock an object for any shared resource.
- When a thread invokes a synchronized method, it automatically acquires the lock for that object.
- The thread releases the lock when it completes its task.

Synchronized Block
------------------
- Synchronized block can be used to perform synchronization on any specific resource of the method.
- If we have 50 lines of code in our method, but if we want to synchronize only 5 lines, we can use synchronized block.
- If we put all the codes of the method in the synchronized block, it will work same as the synchronized method.
- Synchronized block gives class level locking
- Scope of synchronized block is smaller than the method.

Syntax

synchronized (object reference) {

}

Disadvantages of Synchronization
--------------------------------
Synchronization increases the waiting time of threads to execute a task, so only sensitive data manipulation code must be synchronized, not all

Inter-thread communication
==========================
Inter-thread communication or Co-operation is all about allowing synchronized threads to communicate with each other.

It is implemented by following methods of Object class:
- wait()
- notify()
- notifyAll()

1. wait()
---------
Causes current thread to release the lock and wait until either another thread invokes the notify() method or the notifyAll() method for this object, or a specified amount of time has elapsed.

Method	Description
-------------------
public final void wait()throws InterruptedException	waits until object is notified.
public final void wait(long timeout)throws InterruptedException	waits for the specified amount of time.

2. notify()
-----------
This method wakes up a single thread that is waiting on this object's monitor. If any threads are waiting on this object, one of them is chosen to be awakened. The choice is arbitrary and occurs at the discretion of the implementation. 

3) notifyAll()
--------------
This method wakes up all threads that are waiting on this object's monitor.

Producer-Consumer Problem
=========================
🧠 Concept

The Producer-Consumer problem is a classic multithreading synchronization example.
It involves two threads:

=> Producer → generates data and puts it into a shared buffer.
=> Consumer → takes data out of the shared buffer.

The challenge:
➡️ The producer should not add when the buffer is full.
➡️ The consumer should not remove when the buffer is empty.
➡️ Both must work in coordination — not simultaneously modifying the shared resource (`buffer`).

---

⚙️ How It Works

#🟢 `produce()` (Producer)

1. `synchronized` → only one thread can enter at a time.
2. If the buffer is full (`size == capacity`), it calls `wait()`:

   => This releases the lock and pauses the producer.
3. When the consumer removes an item and calls `notify()`, the producer wakes up.
4. Adds an item to the buffer.
5. Calls `notify()` to wake up the consumer.

#🔵 `consume()` (Consumer)

1. `synchronized` → only one thread can enter.
2. If the buffer is empty, the consumer calls `wait()`:

   => This releases the lock and waits for a producer.
3. When the producer adds an item and calls `notify()`, the consumer wakes up.
4. Removes the item from the buffer.
5. Calls `notify()` to wake the producer if it was waiting.

---

🔄 Flow Summary

| Step | Action                 | Effect                   |
| ---- | ---------------------- | ------------------------ |
| 1    | Producer produces item | Adds to buffer           |
| 2    | Consumer consumes item | Removes from buffer      |
| 3    | When full              | Producer waits           |
| 4    | When empty             | Consumer waits           |
| 5    | `notify()`             | Wakes the waiting thread |

---

⚠️ Important Notes

=> `wait()` and `notify()` must be called inside synchronized blocks, or they’ll throw `IllegalMonitorStateException`.
=> `wait()` releases the monitor lock, allowing other threads to acquire it.
=> `notify()` wakes one waiting thread; `notifyAll()` wakes all waiting threads (used if multiple producers/consumers).

## 🧩 Real-World Analogy — MS Word and Multithreading

When you use MS Word (or Google Docs), multiple features work at the same time — thanks to multithreading.

| Thread               | What it does                  | Shared Resource             |
| -------------------- | ------------------------------| --------------------------- |
| Typing Thread        | Takes your keyboard input and | The document text           |
                         updates the document          
| Spell-Check Thread   | Continuously checks spelling  | The same document text      |
                         mistakes 
| Grammar-Check Thread | Analyzes grammar and suggests | The same document text      |
                         improvements
| Autosave Thread      | Saves your document in the    | The same document file/text |
                         background

All these threads work together on the same data, i.e., your document content.

---

⚠️ What Can Go Wrong

If these threads are not synchronized:

=> The spell checker might read half-typed words
=> The grammar checker could get outdated sentences
=> The autosave might save incomplete content

This leads to inconsistent data — a situation called a race condition
(where multiple threads try to access or modify shared data at the same time).

---

✅ How Synchronization Helps

To prevent these problems, MS Word uses synchronization:

=> The typing thread briefly locks the document while editing.
=> The spell/grammar checkers wait or work on a copy of the text.
=> The autosave runs on a stable snapshot of the document.

This ensures each thread works safely without interfering with others —
just like how we used `synchronized`, `wait()`, and `notify()` in our Producer–Consumer example.

---

🧠 Summary

=> Multithreading allows multiple tasks to run at the same time.
=> Shared resources (like our buffer or a document) need controlled access.
=> Synchronization ensures consistent results and prevents race conditions.

---

💬 In short:

> “In MS Word, typing, spell check, and autosave are like multiple threads sharing one resource — your document.
> They must coordinate properly, just like our producer and consumer threads, to work smoothly and avoid conflicts.”
