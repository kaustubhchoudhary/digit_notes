Types of Databases
==================
Below are the types of databases:

1. Relational Databases (RDBMS)

2. NoSQL Databases

   - Key-Value Databases

   - Document-Oriented Databases

   - Graph Databases
   
   - Ex: MongoDB, Apache Cassandra, Redis, CouchDB, Neo4j

Storage Approaches
==================
These are some different types of storage:

1. On-Disk Storage (Traditional databases stored on HDDs/SSDs)

2. In-Memory Storage (Data stored primarily in RAM, e.g., H2, Redis)

3. Cloud Storage (Hosted on cloud platforms, e.g., AWS RDS, Firebase)

4. Hybrid Storage (Combination of in-memory and disk storage)

5. Distributed Storage (Data spread across multiple nodes, e.g., Cassandra)

RDBMS
=====

- RDBMS stands for Relational Data Base Management System

- In an RDBMS, entities are organized according to relationships.

- Some key terms in an RDBMS are:
  database, schema, table, records, properties, constraints, keys, relations, alias, etc.

- Ex: Oracle Database, MySQL, PostgreSQL, Microsoft SQL Server, IBM Db2, MariaDB, SQLite, SAP HANA, Teradata, Firebird

---

PostgreSQL Overview
===================
=> PostgreSQL is an open-source RDBMS server.

=> It can manage multiple databases.

=> When it's installed, it comes with a default database named `postgres`.

=> It was originally named POSTGRES and later renamed to PostgreSQL to reflect its support for SQL.

=> The latest version is 18.x (as of July 2025).

=> PostgreSQL ranks as one of the top relational databases, competing closely with MySQL and Oracle.

=> Many companies such as Instagram, Reddit, Spotify, Apple, IMDB and GoDigit use PostgreSQL.

Schema
======
- In PostgreSQL, a schema is like a folder inside a database that helps organize and group database objects like tables, views, indexes, functions, etc.

So we can say that:

1. Schema is a namespace inside a database

   * It helps prevent name conflicts.
   * For example, we can have two tables named `users`, each in different schemas.

2. Every database starts with a default schema called `public`

   * If we don’t specify a schema, PostgreSQL assumes `public`.

3. Schemas help organize large databases

   * We can group related tables logically (e.g., `sales`, `hr`, `inventory`).

---

🔗 Relationship: Database → Schema → Tables (and other objects)

```
PostgreSQL Server
└── Database: ecommerce
    ├── Schema: customer_data
    │   ├── Table: customers
    │   └── Table: addresses
    └── Schema: order_data
        ├── Table: orders
        └── Table: payments

	└── Database: university
		├── Schema: academics
		│   ├── Table: students
		│   ├── Table: courses
		│   └── Table: enrollments
		└── Schema: administration
			├── Table: departments
			└── Table: faculty

```

---

⚠️ Important:

* Schemas are *inside* databases — not across them.
* We can join tables across schemas within the same database.
* But we cannot join tables across different *databases*.

Table
=====
- Tables contain all the data in a database.
- In tables, data is logically organized in a row-and-column format, similar to a spreadsheet.

---

Row / Tuple
===========
- Each row represents a unique record
- 1 row → 1 record

---

Columns
=======
- Each column represents a field/property/attribute in the record.
- 1 column → 1 property

---

Simply Put
==========
Database → Schemas → Tables → Collection of rows and columns → Collection of records

---

Example:

Schema → `school`

Table1 → `students`

```
Columns → id (PK), name

   id   name  
  ----  ------
   1    Mohit  
   2    Raj
```

Table2 → `mobile_numbers`

```
// Links mobile_no to students  
// Depends on the PK of students  

Columns → id (PK), mobile_no, student_id (FK)

   id   mobile_no   student_id  
  ----  ----------  -----------
   1    9988776655     1  
   2    8877669911     1  
   3    7711990912     2  
   4    8877887788     3  ← not allowed (foreign key violation)
```

- The above tables represent 2 entities — `student` and `mobile number`

- Fields: `id`, `name` in `students`; `id`, `mobile_no`, `student_id` in `mobile_numbers`

- Each row = 1 record

- `id` in both tables = Primary Key

- `student_id` = Foreign Key

PostgreSQL Client/Server Model
==============================
PostgreSQL Server
=================

1. PostgreSQL Server manages the physical memory space and system where the data is stored (persisted).

2. Simply put, it is the software that handles actual data operations.

3. For usage, it must be running as a service (PostgreSQL Service).

4. We can configure it to start automatically with the system boot.

5. Every software runs on an IP and port, so does PostgreSQL Server

   => IP: The digital address of the host machine
   => Port: The endpoint where PostgreSQL runs

6. If PostgreSQL Server is on our own PC, it can be accessed with IP: `127.0.0.1` (localhost)

7. PostgreSQL by default runs on Port: 5432

Refer Image: `03_client_server.png`

---

PostgreSQL Client
=================
=> The data stored by PostgreSQL Server cannot be accessed directly.

=> To interact with it, we need client software or applications.

Refer Image: `03_client_server.png`

Following are some PostgreSQL clients:

1. pgAdmin
2. psql (PostgreSQL Shell)
3. DBeaver - Universal client
4. DataGrip
5. Postico (Mac)
6. Any software application
   => If we connect a Java application with PostgreSQL Server, it will be known as a Java Client.
   => If with Python, it will be Python Client

---

Most used PostgreSQL clients: 

🧩 pgAdmin (GUI for PostgreSQL)

1. Official browser-based GUI tool for managing PostgreSQL databases.
2. Supports visual database design, query execution, role/permission management, and backups.
3. Best suited for beginners and visual learners who prefer point-and-click over writing SQL manually.

---

💻 psql (PostgreSQL Shell)

1. Command-line tool for interacting with PostgreSQL using SQL and meta-commands.
2. Ideal for script automation, quick queries, and power users.
3. Offers features like auto-completion, query history, and administrative tasks (e.g., creating users, databases).

---

🧰 DBeaver (Universal DB Tool)

1. Cross-platform and supports many databases (PostgreSQL, MySQL, Oracle, etc.) in one interface.
2. Offers powerful features like ER diagrams, data export/import, and SQL editing with auto-complete.
3. Great for developers or DB admins working with multiple database systems.

---

PostgreSQL Connectors
=====================
=> To connect one software with another, we need drivers.

=> To connect our applications written in different programming languages, we need to install appropriate drivers on the client side.

=> These drivers are called Connectors.

=> PostgreSQL provides connectors for languages like Java, Python, PHP, etc.

=> Official clients come embedded with drivers
Ex: MySQL Workbench comes embedded with MySQL Drivers
Ex: PgAdmin comes embedded with PostgreSQL Drivers

=> As DBeaver is not specific to any RDBMS, to connect with PostgreSQL we need to download respective drivers.

=> For our Java Applications, with have to download PostgreSQL JDBC Driver (`postgresql-<version>.jar`).

# 📋 Cloning in PostgreSQL

## ✅ Definition:

Cloning means creating a new table based on an existing one.
This may include the structure, the data, or both.

---

## 📂 Types of Cloning

1. Full Cloning

* Copies both the structure and data from the source table.
* Used when you want a working copy of the table with existing data.

--
* Was the structure truly copied in course_1?
--

#🔸 Syntax:

```sql
CREATE TABLE new_table AS SELECT * FROM existing_table;
```

#🔸 Example:

```sql
CREATE TABLE training.course_1 AS SELECT * FROM training.students;
```

#🔸 With Conditions (Filter rows while cloning):

```sql
CREATE TABLE training.course_2 AS 
SELECT * FROM training.students 
WHERE course_fees >= 8000;
```

---

2. Cloning with Custom Columns

* Used when you want some columns from old table and some new ones.

#🔸 Step-by-step Example:

```sql
-- Step 1: Create new table manually with extra column

CREATE TABLE training.course_3 (
    id SERIAL PRIMARY KEY,
    name VARCHAR(30),
    course VARCHAR(20)
);

-- Step 2: Insert selected data from old table
INSERT INTO training.course_3 (name, course)
SELECT student_name, student_course
FROM training.students
WHERE course_fees <= 8000;
```

---

3. Shallow Cloning (Structure Only)

* Copies only the table structure, not the data.
* Useful when you want to reuse schema/columns, but not the rows.

#🔸 Syntax:

```sql
CREATE TABLE new_table (LIKE existing_table INCLUDING ALL);
```

> `INCLUDING ALL` ensures copying of:

> * Columns
> * Data types
> * Default values
> * Constraints
> * Indexes

#🔸 Example:

```sql
CREATE TABLE training.course_4 (LIKE training.students INCLUDING ALL);
```

Removals
========

# 🔹 1. TRUNCATE – *Instantly delete all rows from a table*

➤ Use Case:

Let’s say you want to empty the data in `course_1` (maybe to reload it later), but keep the structure.

✅ Query:

```sql
TRUNCATE TABLE training.course_1 RESTART IDENTITY;
```

🔍 Explanation:

* Empties `course_1` instantly.
* Much faster than DELETE.
* Cannot use `WHERE` clause.
* Resets `SERIAL` or `IDENTITY` values (if present).

---

# 🔹 2. DELETE – *Remove rows selectively*

➤ Use Case:

Suppose you want to remove all rows where `student_course = 'Python'` from `course_2`.

✅ Query:

```sql
DELETE FROM training.course_2 WHERE student_id > 100;
```

🔍 Explanation:

* Removes only matching rows.
* Supports conditions using `WHERE`.
* Retains structure and other rows.

✅ Remove all rows:

```sql
DELETE FROM course_2;
```

---

# 🔹 3. DROP – *Delete entire table structure*

➤ Use Case:

You don’t need `course_3` and `course_4` anymore — remove them entirely.

✅ Query:

```sql
DROP TABLE training.course_1;
```

🔍 Explanation:

* Deletes the table itself.
* All data, structure, and indexes are gone.
* Cannot be recovered unless you have a backup.
* Use `CASCADE` if there are dependencies:

```sql
DROP TABLE course_3 CASCADE;
```

DROP multiple tables

```sql
DROP TABLE training.course_2, training.course_3, training.course_4;
```

DROP Schema
===========

DROP SCHEMA schema_name CASCADE;

```sql
DROP SCHEMA training CASCADE;
```

Notes:
Without CASCADE, you might get an error if the schema contains any objects.
CASCADE will permanently delete all tables, views, sequences, functions, etc., in that schema.

Drop Database
=============

## ✅ Steps to Drop `company` Database in DBeaver

🔹 Step 1: Ensure You Are Not Connected to `company`

* In the **Database Navigator**, locate the `company` database.
* If it shows a **green dot** (active connection), **right-click on `company` ➝ `Disconnect`.

---

🔹 Step 2: Make Sure You're Connected to Another Database

* If you're not connected to any other database, click on the `postgres` database (default one).
* If not connected, right-click `postgres` ➝ `Connect`.

---

🔹 Step 3: Terminate Any Sessions (Optional but Safe)

> If multiple users/connections are using `company`, you need to terminate them manually.

1. Open a **SQL Editor** tab connected to `postgres`.
2. Run:

   ```sql
   SELECT pg_terminate_backend(pid)
   FROM pg_stat_activity
   WHERE datname = 'company' AND pid <> pg_backend_pid();
   ```

---

🔹 Step 4: Drop the Database

* Right-click on the `company` database ➝ choose **Delete**.
* A dialog will appear. Confirm that:

  * You're deleting the **database**, not just disconnecting.
  * The SQL shown is `DROP DATABASE company;`
* Click **Yes / OK** to execute.

---

## 🧹 Result

The  `company` database will be permanently deleted from the PostgreSQL server.
