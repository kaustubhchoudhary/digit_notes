SQL
===
What is SQL?

-> Client programs can talk with the PostgreSQL database server only with commands.

-> These command are known as SQL

-> SQL stands for Structured Query Language

-> It is the official language to communicate with any RDBMS software

-> Simply put, to work with any database we need to write SQL Instructions

-> SQL instructions are also known as SQL Queries

-> SQL lets us access and manipulate databases

---

What Can SQL Do?

SQL can:

- retrieve data from a database
- insert, update, and delete records in/from a database
- create new databases and tables
- alter existing database objects (tables, constraints, columns)
- delete database objects such as tables or databases
- control access to data using permissions
- enforce data integrity using constraints

👉 In short:
SQL allows us to define the structure of data, manipulate the data, and control access to it.

---

CRUD Operations
---------------
- CRUD represents the four basic operations that we can perform on data stored in a database.
[C]reate
[R]ead
[U]pdate
[D]elete

- Create: Adds new data (records/rows) into an existing table using the `INSERT` statement.

- Read: Fetches existing data from one or more tables using the `SELECT` statement without changing it.

- Update: Changes existing data in a table using the `UPDATE` statement, usually with a `WHERE` condition.

- Delete: Removes existing records from a table using the `DELETE` statement, either selectively or completely.

---

SQL Commands
============
SQL uses certain commands like Create, Drop, Insert, etc. to carry out the required tasks.
 
These SQL commands are mainly categorized into following 5 categories as: 

1. DDL - Data Definition Language
2. DML - Data Manipulation Language
3. DQL - Data Query Language
4. DCL - Data Control Language
5. TCL - Transaction Control Language

---

SQL DDL
=======

SQL DDL (Data Definition Language)

* DDL is used to define and manage the structure of database objects.
* It works on schema-level objects, not on individual records.
* DDL commands are used to create, modify, and delete database structures.
* Changes made using DDL are auto-committed in most databases.
* DDL affects objects such as databases, tables, views, and constraints.

Common DDL Commands

* `CREATE`
* `ALTER`
* `DROP`
* `TRUNCATE`

👉 In short:
DDL defines what the database looks like and how it is structured.

✅ 8. Update Queries

#➤ Update Single Record

```sql
UPDATE training.students 
SET student_course = 'Advance Java', course_fees = 8000 
WHERE student_id = 101;
```

#➤ Update Multiple Rows

```sql
UPDATE training.students 
SET course_fees = 10000 
WHERE student_course = 'Advance Java';
```

---

✅ 9. Delete Record

```sql
DELETE FROM training.students 
WHERE student_email = 'yash@hotmail.com';
```

---

✅ 10. DQL: SELECT Filters

```sql
-- Simple select
SELECT * FROM training.students;

-- WHERE clause
SELECT * FROM training.students WHERE course_fees > 8000;

-- AND / OR
SELECT * FROM training.students 
WHERE course_fees > 8000 AND student_course = 'Advance Java';

-- IN
SELECT * FROM training.students 
WHERE student_course IN ('Core Java', 'Core Python');

Same as

SELECT * FROM training.students 
WHERE student_course = 'Core Java' OR student_course = 'Core Python';

-- LIKE
SELECT * FROM training.students 
WHERE student_email LIKE '%@gmail.com';

-- BETWEEN
SELECT * FROM training.students 
WHERE course_enrollment_date BETWEEN '2023-01-01' AND '2023-06-30';
```

# 📋 Cloning in PostgreSQL

## ✅ Definition:

Cloning means creating a new table based on an existing one.
This may include the structure, the data, or both.

---

## 📂 Types of Cloning

1. Full Cloning

* Copies both the structure and data from the source table.
* Used when you want a working copy of the table with existing data.

--

#🔸 Syntax:

```sql
CREATE TABLE new_table AS SELECT * FROM existing_table;
```

#🔸 Example:

```sql
CREATE TABLE training.course_1 AS SELECT * FROM training.students;
```

Result:
=> Creates a new table `course_1`
=> Copies both columns and data from `students`
=> Does not copy primary key, foreign keys, indexes, or unique constraints
=> Does copy `NOT NULL` constraint

* Compare setting of both tables

#🔸 With Conditions (Filter rows while cloning):

```sql
CREATE TABLE training.course_2 AS 
SELECT * FROM training.students 
WHERE course_fees >= 8000;
```

---

2. Cloning with Custom Columns

* Used when you want some columns from old table and some new ones.

#🔸 Step-by-step Example:

```sql
-- Step 1: Create new table manually with extra column

CREATE TABLE training.course_3 (
    id SERIAL PRIMARY KEY,
    name VARCHAR(30),
    course VARCHAR(20)
);

-- Step 2: Insert selected data from old table
INSERT INTO training.course_3 (name, course)
SELECT student_name, student_course
FROM training.students
WHERE course_fees <= 8000;
```

---

3. Shallow Cloning (Structure Only)

* Copies only the table structure, not the data.
* Useful when you want to reuse schema/columns, but not the rows.

#🔸 Syntax:

```sql
CREATE TABLE new_table (LIKE existing_table INCLUDING ALL);
```

> `INCLUDING ALL` ensures copying of:

> * Columns
> * Data types
> * Default values
> * Constraints
> * Indexes

#🔸 Example:

```sql
CREATE TABLE training.course_4 (LIKE training.students INCLUDING ALL);
```

Removals
========

# 🔹 1. TRUNCATE – *Instantly delete all rows from a table*

➤ Use Case:

Let’s say you want to empty the data in `course_1` (maybe to reload it later), but keep the structure.

✅ Query:

```sql
TRUNCATE TABLE training.course_1 RESTART IDENTITY;
```

🔍 Explanation:

* Empties `course_1` instantly.
* Much faster than DELETE.
* Cannot use `WHERE` clause.
* Resets `SERIAL` or `IDENTITY` values (if present).

---

# 🔹 2. DELETE – *Remove rows selectively*

➤ Use Case:

Suppose you want to remove all rows where `student_course = 'Python'` from `course_2`.

✅ Query:

```sql
DELETE FROM training.course_2 WHERE student_id > 100;
```

🔍 Explanation:

* Removes only matching rows.
* Supports conditions using `WHERE`.
* Retains structure and other rows.

✅ Remove all rows:

```sql
DELETE FROM course_2;
```

---

# 🔹 3. DROP – *Delete entire table structure*

➤ Use Case:

You don’t need `course_3` and `course_4` anymore — remove them entirely.

✅ Query:

```sql
DROP TABLE training.course_1;
```

🔍 Explanation:

* Deletes the table itself.
* All data, structure, and indexes are gone.
* Cannot be recovered unless you have a backup.
* Use `CASCADE` if there are dependencies:

```sql
DROP TABLE course_3 CASCADE;
```

DROP multiple tables

```sql
DROP TABLE training.course_2, training.course_3, training.course_4;
```

DROP Schema
===========

DROP SCHEMA schema_name CASCADE;

```sql
DROP SCHEMA training CASCADE;
```

Notes:
Without CASCADE, you might get an error if the schema contains any objects.
CASCADE will permanently delete all tables, views, sequences, functions, etc., in that schema.

Drop Database
=============

## ✅ Steps to Drop `company` Database in DBeaver

🔹 Step 1: Ensure You Are Not Connected to `company`

* In the Database Navigator, locate the `company` database.
* If it shows a green dot (active connection), right-click on `company` ➝ `Disconnect`.

---

🔹 Step 2: Make Sure You're Connected to Another Database

* If you're not connected to any other database, click on the `postgres` database (default one).
* If not connected, right-click `postgres` ➝ `Connect`.

---

🔹 Step 3: Terminate Any Sessions (Optional but Safe)

> If multiple users/connections are using `company`, you need to terminate them manually.

1. Open a SQL Editor tab connected to `postgres`.
2. Run:

   ```sql
   SELECT pg_terminate_backend(pid)
   FROM pg_stat_activity
   WHERE datname = 'company' AND pid <> pg_backend_pid();
   ```

---

🔹 Step 4: Drop the Database

* Right-click on the `company` database ➝ choose Delete.
* A dialog will appear. Confirm that:

  * You're deleting the database, not just disconnecting.
  * The SQL shown is `DROP DATABASE company;`
* Click Yes / OK to execute.

---

## 🧹 Result

The  `company` database will be permanently deleted from the PostgreSQL server.
