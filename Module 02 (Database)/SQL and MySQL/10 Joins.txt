What is a JOIN?

> A JOIN is used to retrieve data from multiple related tables using a common column (usually PK–FK).

After normalization, data is split into:

* `users`
* `orders`
* `products`
* `order_items`

👉 Joins help us reconstruct meaningful information from these tables.

Refer fig: 05_sql_joins.png

---

Relationships in Our Schema

* `users.user_id` ↔ `orders.user_id`
* `orders.order_id` ↔ `order_items.order_id`
* `products.product_id` ↔ `order_items.product_id`

---

# 1. INNER JOIN

Definition

Returns only matching records from both tables.

---

Syntax

```sql
SELECT columns
FROM table1
INNER JOIN table2
ON condition;
```

---

Example: Users who placed orders

```sql
SELECT u.user_name, o.order_id, o.order_date
FROM users u
INNER JOIN orders o
ON u.user_id = o.user_id;
```

👉 Only users with orders are shown.

---

Example: Orders with product details

```sql
SELECT o.order_id, p.product_name, oi.qty
FROM orders o
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.product_id;
```

---

# 2. LEFT JOIN (LEFT OUTER JOIN)

Definition

Returns all records from the left table, and matching records from the right table.
If no match → `NULL`.

---

Syntax

```sql
SELECT columns
FROM table1
LEFT JOIN table2
ON condition;
```

---

Example: All users (even if no orders)

```sql
SELECT u.user_name, o.order_id
FROM users u
LEFT JOIN orders o
ON u.user_id = o.user_id;
```

👉 Users without orders will still appear.

---

Use Case

* Find users who never placed an order
* Audit missing relationships

---

# 3. RIGHT JOIN (RIGHT OUTER JOIN)

Definition

Returns all records from the right table, and matching records from the left table.

---

Syntax

```sql
SELECT columns
FROM table1
RIGHT JOIN table2
ON condition;
```

---

Example: All orders with user info

```sql
SELECT u.user_name, o.order_id
FROM users u
RIGHT JOIN orders o
ON u.user_id = o.user_id;
```

👉 Practically same as LEFT JOIN with table order reversed.

---

🔎 Note

> RIGHT JOIN is rarely used in real projects.
> Here we want all the orders that exist without users
> As the data in orders table is only possible with users, it makes no sense
> We can get data only if some orders are made by non-registerd users

---

# 4. FULL JOIN (Conceptual in MySQL)

Definition

Returns all matching and non-matching records from both tables.

⚠️ MySQL does NOT support FULL JOIN directly

---

FULL JOIN using UNION

```sql
SELECT u.user_name, o.order_id
FROM users u
LEFT JOIN orders o
ON u.user_id = o.user_id

UNION

SELECT u.user_name, o.order_id
FROM users u
RIGHT JOIN orders o
ON u.user_id = o.user_id;
```

---

# 5. SELF JOIN

Definition

A table joined with itself.

👉 Used when rows in the same table relate to each other.

---

Syntax

```sql
SELECT a.col, b.col
FROM table a
JOIN table b
ON condition;
```

---

Example (Conceptual)

If `users` had a `referred_by` column:

```sql
SELECT u1.user_name AS user,
       u2.user_name AS referred_by
FROM users u1
LEFT JOIN users u2
ON u1.referred_by = u2.user_id;
```

---

# 6. CROSS JOIN

Definition

Returns Cartesian product (every row × every row).

---

Syntax

```sql
SELECT *
FROM table1
CROSS JOIN table2;
```

---

Example

```sql
SELECT u.user_name, p.product_name
FROM users u
CROSS JOIN products p;
```

👉 Produces users × products combinations
⚠️ Rarely used in real systems.

---

# Important Join Rules (Must Remember)

* Always join using PK–FK
* Use table aliases (`u`, `o`, `p`)
* Avoid joining on non-key columns
* Understand result size before executing

---

# Normalization + Joins (Key Insight)

> Normalization removes redundancy; joins restore meaning.

They are complementary, not opposite.

---

Closing Lines

You can present it like this:

| Join            | Purpose                           | Usage Frequency |
| --------------- | --------------------------------- | --------------- |
| INNER JOIN      | Matching data                     | Most Used       |
| LEFT JOIN       | Include missing data              | Very Common     |
| RIGHT JOIN      | Reverse of LEFT JOIN              | Rare            |
| FULL OUTER JOIN | Everything (via `UNION` in MySQL) | Very Rare       |
| SELF JOIN       | Same table relationship           | Occasional      |
| CROSS JOIN      | All possible combinations         | Very Rare       |


* Master `INNER JOIN` and `LEFT JOIN` first-they account for the vast majority of SQL joins you'll write.
* Learn `SELF JOIN` for hierarchical relationships (e.g., employees and managers).
* Know that `RIGHT JOIN`, `FULL OUTER JOIN`, and `CROSS JOIN` exist, but they're used much less frequently.

Practice questions
==================

1. List all users along with their order IDs

Concept: `INNER JOIN`

```sql
SELECT u.user_name, o.order_id
FROM users u
INNER JOIN orders o
ON u.user_id = o.user_id;
```

---

2. List all users, including those who have not placed any orders

Concept: `LEFT JOIN`

```sql
SELECT u.user_name, o.order_id
FROM users u
LEFT JOIN orders o
ON u.user_id = o.user_id;
```

---

3. Find users who have NOT placed any orders

Concept: `LEFT JOIN + NULL check`

```sql
SELECT u.user_name
FROM users u
LEFT JOIN orders o
ON u.user_id = o.user_id
WHERE o.order_id IS NULL;
```

---

4. Display order ID, product name, and quantity for all orders

Concept: Multi-table `INNER JOIN`

```sql
SELECT o.order_id, p.product_name, oi.qty
FROM orders o
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.product_id;
```

---

5. Display user name, order ID, and order date

Concept: Join parent → child

```sql
SELECT u.user_name, o.order_id, o.order_date
FROM users u
INNER JOIN orders o
ON u.user_id = o.user_id;
```

---

6. Find total quantity of each product sold

Concept: Join + aggregation

```sql
SELECT p.product_name, SUM(oi.qty) AS total_qty_sold
FROM products p
INNER JOIN order_items oi
ON p.product_id = oi.product_id
GROUP BY p.product_name;
```

---

7. Find total number of orders placed by each user

Concept: `LEFT JOIN + COUNT`

```sql
SELECT u.user_name, COUNT(o.order_id) AS total_orders
FROM users u
LEFT JOIN orders o
ON u.user_id = o.user_id
GROUP BY u.user_name;
```

---

8. Display order ID and total amount of each order

Concept: Join + calculation

```sql
SELECT o.order_id,
       SUM(p.price * oi.qty) AS order_total
FROM orders o
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.product_id
GROUP BY o.order_id;
```

---

9. Find users who ordered “Campus Running Shoes”

Concept: Multi-table filtering

```sql
SELECT DISTINCT u.user_name
FROM users u
INNER JOIN orders o ON u.user_id = o.user_id
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.product_id
WHERE p.product_name = 'Campus Running Shoes';
```

---

🔟 Display users and the products they have ordered

Concept: Full relationship traversal

```sql
SELECT u.user_name, p.product_name
FROM users u
INNER JOIN orders o ON u.user_id = o.user_id
INNER JOIN order_items oi ON o.order_id = oi.order_id
INNER JOIN products p ON oi.product_id = p.product_id;
```
