
# Assignment: University Student Result Management System

## Objective

Develop a Java application to process student records stored in a file, evaluate their academic results, and generate a result report using modern Java features.

---

# Functional Requirements

## 1. Create an Enum

Create an enum named `Department` containing the following constants:

* COMPUTER_SCIENCE
* INFORMATION_TECHNOLOGY
* ELECTRONICS
* MECHANICAL
* CIVIL

---

## 2. Create a Custom Annotation

Create a custom annotation named `@StudentInfo` with the following elements:

* `String createdBy();`
* `String version();`
* `String[] reviewers();`

Annotate the `Student` record using this annotation.

---

## 3. Create a Record

Create a record named `Student` containing the following fields:

* int rollNo
* String name
* Department department
* int[] marks
* LocalDate dateOfBirth

### Additional Requirements

* Use a *compact constructor* to validate:

  * Roll number must be greater than zero.
  * Exactly five subject marks must be supplied.
  * Each mark must be between 0 and 100.
* Create a method

```java
double getPercentage()
```

to calculate the percentage.

---

## 4. Use Varargs

Inside the `Student` record, create the following method:

```java
double calculateAverage(int... marks)
```

The method should calculate and return the average of all supplied marks.

Call this method from `getPercentage()`.

---

## 5. Create a Sealed Class Hierarchy

Create a sealed class named `Result`.

```
                Result
                   │
      ┌────────────┼────────────┐
      │            │            │
 PassResult   FailResult   DistinctionResult
```

Requirements:

* `Result` must be sealed.
* All three subclasses must be `final`.
* Each subclass must override

```java
String getResultMessage();
```

Expected outputs:

```
Pass
Fail
Passed with Distinction
```

---

## 6. Read Student Data from a File

Create a file named

```
students.txt
```

Sample data:

```
101,Rahul,COMPUTER_SCIENCE,75|82|91|68|88,2005-04-15
102,Priya,INFORMATION_TECHNOLOGY,30|28|35|40|32,2004-11-21
103,Aman,ELECTRONICS,95|94|91|90|96,2005-02-18
104,Neha,CIVIL,70|65|75|72|68,2005-09-10
```

Read all student records using *BufferedReader*.

---

## 7. Use Exception Handling

Handle all possible exceptions appropriately.

Examples include:

* File not found
* Invalid department name
* Invalid date format
* Invalid marks
* Invalid number format
* Incorrect file format

If a student's record is invalid, display a suitable error message and continue processing the remaining records.

---

## 8. Determine Student Result

Use the following rules:

| Percentage   | Result Class      |
| ------------ | ----------------- |
| Below 40     | FailResult        |
| 40 to 74.99  | PassResult        |
| 75 and above | DistinctionResult |

Create and return the appropriate subclass object.

---

## 9. Generate Report

Display the following information for every student:

```
---------------------------------------------------------
Roll No      : 101
Name         : Rahul
Department   : COMPUTER_SCIENCE
Percentage   : 80.80
Result       : Passed with Distinction
---------------------------------------------------------
```

---

## 10. Save Report

Write the complete report into

```
result.txt
```

using *BufferedWriter*.

---

## 11. Use the `var` Keyword

Use the `var` keyword wherever local variable type inference is appropriate.

Examples:

```java
var reader = new BufferedReader(new FileReader("students.txt"));

var student = new Student(...);

var result = evaluateResult(student);

var percentage = student.getPercentage();
```

---

### Learning Outcome

After completing this assignment, students will have applied:

* *Records* for immutable data modeling.
* *Enums* for type-safe department values.
* *Custom annotations* for metadata and optional reflection.
* *Sealed classes* to model a restricted result hierarchy.
* *File I/O* to read input and generate reports.
* *`var`* for local variable type inference.
* *Varargs* to process a variable number of marks.
* *Exception handling* to build a robust application that continues processing even when some input records are invalid.
